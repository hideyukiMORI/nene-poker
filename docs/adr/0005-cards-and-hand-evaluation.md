# ADR 0005 — 札はランクとスートの閉じた enum、札の集まりは 64 ビットの整数、役判定は 7 枚から最良の 5 枚をビットで直接決める 1 経路

- 状態: 受理
- 日付: 2026-10-26
- Issue: #3
- 影響する規則: ARC-001 / ARC-003 / ARC-007 / SWF-001 / SWF-002 / SWF-007 / QLT-008

## 文脈

テキサスホールデムの役は、各席の手札 2 枚と場札 5 枚の 7 枚から最良の 5 枚で決まる（FR-02a）。役判定はショーダウンの分配（Core・Phase 3-2）と
勝率の見積もり（Engine・Phase 3-5）の両方が使う。見積もりは 1 行動に数千回の役判定を呼ぶので、速さが見た目の強さに効く。
一方で「役の強さの比較」は意味の正本で、速さのために第 2 の経路を作らない（ARC-001）。

Phase 0 の実測（ADR 0001）: 64 ビットの桁あふれは `&` 付きの演算子で書く（X-g・X-h）。`Double.squareRoot()` は標準モジュールを import しないとリンクできない（X-i・X-j）。

## 決定

1. **札**: `Rank`（2〜A の 13 個・生の値は 2 を 0 とする添字）と `Suit`（スペード・ハート・ダイヤ・クラブ）の閉じた enum の組 `Card`。どの組も 1 枚ずつあるので、`Card(rank:suit:)` で作る（拒否する入力が無い）
2. **札の文字列の表記**: `CardNotation` の 1 経路だけが読み書きする。ランク 1 文字（`2`〜`9` `T` `J` `Q` `K` `A`）＋スート 1 文字（`s` `h` `d` `c`）。
   読めない文字列は閉じた理由（`CardDecodeRejection`）で返す。画面の文字もこの記号を使い、Render は色と配置だけを足す（第 2 の表記を作らない）。
   スート記号 `♠♥♦♣` は使わない（FR-07b。Emoji=Yes で前景色が効かない）
3. **札の集まり**: `CardSet` は 64 ビットの整数。スートごとに 16 ビットの区画を取り、下位 13 ビットがランク。同じ札は 1 度しか入らない
4. **山札**: `Deck.ordered`（52 枚）と `Deck.dealingOrder(using:)`（渡された乱数源で標準ライブラリの `shuffled(using:)` を呼ぶ）。乱数源は引数で受け取り、Core は乱数源を作らない（ARC-007）
5. **役の強さ**: `HandStrength` は役の種類（`HandCategory`・9 種類の閉じた enum）と比べる順のランクを 1 つの整数に詰めた値（種類を上位に・ランクを 4 ビットずつ）。
   整数の大小がそのまま役の強さの大小で、2 人の比較は `HandStrength` の `<` と `==` だけ。スートは比較に入らない。
   ロイヤルフラッシュは A を頭にしたストレートフラッシュで、別の種類にしない（画面の名前は Render が決める）
6. **役判定**: `HandEvaluator.strength(of:)` が 5〜7 枚の `CardSet` から最良の 5 枚の強さを返す唯一の経路。21 通りの 5 枚を作らず、
   スートごとのランクの 13 ビットと、ランクごとの枚数（4 枚・ちょうど 3 枚・ちょうど 2 枚・1 枚以上）のビットから直接決める。
   - フラッシュを最初に見る。7 枚以下では、同じスートの 5 枚の外に札が 2 枚しか無いので、フラッシュとフォーカード・フルハウスは同時に起きない
   - ストレートは A を 1 としても数える（5-4-3-2-A＝ホイールの頭は 5）。K-A-2 のような回り込みは無い
   - 配列を作らない（見積もりの回数のため）。`ranks`（比べる順のランクの配列）は表示とテストのための読み出しで、比較には使わない
7. 浮動小数点は Core では使わない

## 強制

- **active**: ランク・スート・役の種類は閉じた enum で、`switch` の全捕捉は CNF-013 が拒む。乱数源の引数は CNF-012（`using:` の無い `shuffled(...)` を拒む）
- **planned**: 「役の比較が `HandStrength` の 1 経路だけ」はレビュー事項（ARC-001）。正しさは ADR 0006 のテストで見る

## 結果

- 2026-10-26 の WSL2 の release 構成で、52 枚から 7 枚の全 133,784,560 通りの役判定が約 3.7 秒（1 回 30 ナノ秒弱）
- 失うもの: 役判定の中身は整数のビットの操作で、読みにくい。全数の公表値と 21 通りの比較との一致（ADR 0006）で正しさを支える

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 7 枚から 21 通りの 5 枚を作り、5 枚の判定の最大を取る | 素直だが 21 倍遅い。見積もりの回数が減り、性格の差（FR-06）の幅が狭まる。テストで基準として使う（ADR 0006） |
| 既製の高速な評価表（素数の積・大きな参照表）を写す | 外部のポーカーの評価器を使わない方針（REQUIREMENTS 第 3 節）。表を自前で作るにしても、生成コードの規則（SWF-009）が要る |
| 札を 0〜51 の整数だけで持つ | 境界のプリミティブ執着（SWF-001）。ランクとスートを閉じた enum にし、ビットの位置は Core の中だけに置く |
| ロイヤルフラッシュを役の種類に足す | A を頭にしたストレートフラッシュと強さの比較が同じで、種類を増やすと比較の経路が増える。出典の数え方の違いはテストの側で足し合わせる |
| 札の表記を Render だけに置き、テストは別の読み方を持つ | 表記が 2 か所に割れる（ARC-001）。Core の 1 経路を Render とテストが使う |
| 山札を切る関数を `shuffled(using:)` と名付ける | 宣言の引数の名前（`using generator:`）が CNF-012 の字句検査に `using:` の無い呼び出しとして見える。検査を緩めず、名前を `dealingOrder(using:)` にした |
