# ADR 0010 — 実機（Windows Terminal）の画面写真で、札・4 色・VIEW の両モード・文字幅を確かめ、ハンドの終わりの席のチップを分配の後の値にする

- 状態: 受理
- 日付: 2026-10-26
- Issue: #9
- 影響する規則: QLT-013 / ARC-011 / QLT-008

## 文脈

単体テストと疑似端末は Windows Terminal での見え方の証拠にならない（QLT-013）。Phase 3-4 で、兄弟と同じ方法で実機の画面写真を撮った
（2026-10-26・WSL2 Ubuntu 22.04・Windows Terminal・既定の 120 × 30・ウィンドウ 1859 × 1079 ピクセル・`wt.exe` を配列の引数で起動・
`FindWindow` にクラス名 `CASCADIA_HOSTING_WINDOW_CLASS`・`PrintWindow(hwnd, hdc, 2)`・撮影側は `SetProcessDPIAware`・撮ったあと自分の実行ファイルだけを `pkill -f '^<フルパス>'` で止めた）。
写真は作業木の外（スクラッチパッドの `poker-shots/`）に置いた（`33-you-1.png`・`33-you-2.png`・`34-all-1.png`・`34-result-2.png`・`34-showdown-you.png`・直した後の `34-showdown-fixed.png`）。

撮った場面: プリフロップ（VIEW: YOU）・ターンの途中（YOU）・同じシードの同じ場面（VIEW: ALL）・全員が降りて終わったハンド（YOU）・ショーダウン（YOU）。

## 見えたこと

1. **文字幅**: 罫線の枠（`┌─┐│`）・HUD の棒（`█░▕▏`）・カーソル `▌` は 1 桁で描かれ、配置は崩れなかった。画面のほかの文字は ASCII だけ
2. **札**: 札の地（`cardFace`）のブロックの上で、ランクとスートの文字は読めた。小さい札（` Ah `）・大きい札（6 × 4）・裏（` ## `）・降りた札（ALL の控えめな地・YOU の `--`）・
   まだ開いていない場札（`--`）が区別できた
3. **4 色のデッキ**: スペード（黒）・ハート（赤）・ダイヤ（青）・クラブ（緑）が見分けられ、`s h d c` の文字でも区別できた。ダイヤの青は札の地の上でやや暗いが読める
4. **VIEW**: 同じシードの同じ場面で、YOU はメインの子以外が裏、ALL は全員が表になり、行動の列（LOG）は同じだった。ショーダウンでは YOU でも残った 2 人の札が表になり、
   全員が降りたハンドの勝者の札は YOU で裏のままだった
5. 🔴 **Phase 3-3 の写真で見つけて直したもの**: プリフロップのブラインドだけで `POT 20 + SIDE 10` と出た（ADR 0008 の決定 11 で直した）
6. 🔴 **この段で見つけたもの**: ハンドの終わりの画面で、卓の席の下のチップが分配の前の値（例: 勝った人が `39`）のまま、HUD の STACKS は分配の後の値（`4,097`）で、食い違っていた
7. フォントの `D` の字形（横棒の入った D）は端末のフォントの字形で、画面の文字は `D` のまま（変えない）

## 決定

1. ハンドが終わったら、卓の席の下のチップも分配の後の値（`HandResult.stacks`）にする。HUD の STACKS と同じ値になる
2. 写真の手順（起動・撮影・後始末）は、Phase 3-6 と Phase 4 の README の写真でもそのまま使う
3. 白抜きのスート記号 `♤♡♢♧` は使わない（ASCII の `s h d c` で 4 色が十分に見分けられた。Ambiguous の幅の罠を持ち込む理由が無い）

## 強制

- **active**: ハンドの終わりの席のチップが分配の後の値であること（`make test`）
- **不能**: 見え方そのもの（色・読みやすさ）は機械では見られない。写真で確かめた（QLT-013）。直した後の写真（`34-showdown-fixed.png`）で、勝った人の席の下が `4,097` で STACKS と一致した。施主の確認は未

## 結果

- 札・4 色・VIEW の両モードが実機で読めることを確かめた
- 失うもの: 写真は手作業の確認で、テーマや配置を変えたら撮り直す必要がある

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 白抜きのスート記号に替える | ASCII で読めた。Ambiguous の幅の罠と、端末ごとの字形の差を持ち込む |
| 卓の席の下に分配の前のチップと獲得額を並べる | 画面仕様に無い要素を足すことになる。STACKS と同じ値にそろえるだけにした |
