# ADR 0008 — 卓の画面は 112 × 28 の大の配置で描き、札は札の地の色のブロックに ASCII で、VIEW のモードは Render の入力にだけ置く

- 状態: 受理
- 日付: 2026-10-26
- Issue: #7
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / ARC-011 / SWF-014 / QLT-008

## 文脈

Phase 3-3 は、合法な行動から乱数で選ぶ 4 人の卓を画面に出し、`v` のトグル・卓の終わりと次の卓・`q`・端末の復元を通す段である（指示書 第 4 節）。
画面の正本は施主の指定で作った画面仕様（B 案・大の配置は約 112 × 28）。兄弟の画面写真の罠（Emoji=Yes の文字は前景色が効かない・Ambiguous の幅）を最初から避ける。

## 決定

### 卓の列（Engine）

1. `TableSeries` が卓の列の値を持つ: いまのハンドを配る前の卓・いまのハンド・段階（ハンドの途中／ハンドの終わり／卓の終わり）・何卓目か・席のキャスト・通算の優勝・このハンドの出来事。
   1 歩で「行動 1 つ」か「場札を開く 1 回」か「次のハンド」か「次の卓」に進む。時計を知らず、乱数は引数で受け取る
2. ハンドの終わりは 1 歩ぶん結果を見せ（合成ルートが結果の時間だけ待つ）、次の歩で次のハンドを配る。卓の終わり（1 人が全チップ）は優勝を見せ、次の歩で次の卓を始める。
   次の卓では 4 名を乱数で席に並べ直し（南に座った人がメインの子・FR-07）、親を乱数で決める
3. 仮の AI `RandomPolicy` は Core の `LegalActions` から乱数で選ぶ（ARC-001）。額は合法な範囲から一様に、オールインは 20 回に 1 回だけ選ぶ（毎回の候補にすると卓が数ハンドで終わる）。Phase 3-5 で置き換える
4. 製品の卓の決まり（`TableSetup.standard`）は仮の値（初期 1,500・ビッグブラインド 20 から 10 ハンドごとに上がる 14 段階）。Phase 3-5 で AI を入れてから測って決める
5. キャスト 4 名（REQUIREMENTS の Q7・兄弟 3 作と別の名前）: `BLUFF.EXE`・`NIT.BAK`・`TILT.SH`・`ODDS.CSV`。名前はポーカーの言葉（はったり・固い人・熱くなること・確率）から。
   最初は `FOLD.BAK` と `ALLIN.SH` にしたが、LOG の `FOLD all-in 717` のように短い名前が行動の語と区別できなかったので替えた。性格とセリフは Phase 3-5・3-6 で足す

### 画面（Render）

6. **大の配置**（112 × 28）: 上端に題の帯、左に卓の枠（76 × 22）、右に HUD（33 桁）、卓の下に COMMS の 2 行（Phase 3-6 でセリフ）、下端にキーの帯。
   入らない端末では必要な大きさを 1 行で出して待つ。縮小版（80 × 24）は Phase 3-6 で足す
7. **席**: 南（メインの子）は手前に大きい札（6 桁 × 4 行・2 行目の左にランク・3 行目の右にスート）、西・北・東は小さい札（4 桁 × 1 行・` Ah `）。
   名前の行に手番の印 `>`（`▶` は Ambiguous で Emoji の異体字もあるので使わない）と親の `(D)`、札の横に `SB` / `BB`、その下にチップと直前の行動の 1 語
   （`FOLD` `CHECK` `CALL 80` `BET 80` `RAISE 240` `ALL-IN`。降りた・オールインはハンドの終わりまで、ほかはそのストリートの間）。飛んだ席は `OUT`
8. **札**: 札の地の色（`cardFace`）で塗った偶数桁のブロックに、Core の `CardNotation` の記号（ランク `A K Q J T 9`…`2`・スート `s h d c`）をスートの色で置く（4 色のデッキ）。
   裏は `cardBack` の地に `##`。降りた札は ALL では `foldedFace` の地に控えめな文字、YOU では空の枠 `--`。まだ開いていない場札も `--`
9. **VIEW のモード** `ViewMode`（`you` 既定・`all`）は Render の型で、`DisplayOptions` の中にあり、持ち主は合成ルート。Core と Engine は Render を import できない（ADR 0004）ので、
   モードが卓の進み方・乱数・セリフに入る経路が物理的に無い。`v` は合成ルートの表示の値だけを替える
10. **どの札を表にするか**（`CardVisibility`）: メインの子は常に表。ALL は全員表。YOU はほかの席が裏で、ショーダウンで見せた席と、行動できる人が 1 人以下になって場札を開いていくだけになった後の残りの人は表。
    全員が降りて終わったハンドの勝者の札は YOU では見せない（画面仕様の States and Interactions）
11. **ポット**: 卓の中央に `POT 360 + SIDE 120 + 40`。段の作り方は Core の `PotDivision.layers` の 1 経路（ハンドの途中も分配と同じ経路）
12. **いまの役の名前**: 南の札の右に、場札が 3 枚以上開いたら Core の役判定の結果をそのまま言葉にして出す（`PAIR OF QUEENS`・`FULL HOUSE, KINGS OVER THREES`・`ROYAL FLUSH`）。
    プリフロップ（2 枚）では出さない（5 枚未満の役判定の経路を作らない）。勝率や推奨手は出さない
13. **HUD**: MATCH（卓・ハンド・ブラインドと段階・親）・STACKS（YOU・W・N・E の棒と額・飛んだ席は `OUT`）・LOG（このハンドの出来事・最新が下・次に打つ席にカーソル）・
    RESULT（ハンドの終わりは勝者とスプリットと額と役の名前、卓の終わりは優勝と通算と次の卓までの秒読み）
14. **テーマ**: NEON の 1 つだけを置き、画面仕様の Design Tokens（卓の地・卓の文字・札の地・スート 4 色・裏と裏の文字・降りた札の地と文字・手番・チップの棒）を足した。
    12 テーマと `t` は Phase 3-6 で足す。キーの帯は `[q] QUIT  [v] VIEW: YOU │ <ストリート> │ LAST <直前の行動>`

## 強制

- **active**: 画面の文字は ASCII と枠の字形だけで、スート記号 `♠♥♦♣♤♡♢♧` と `▶` が無いこと（`make test`）・文字のあるセルの前景と背景が 4.5:1 以上（両方の VIEW）・
  Design Tokens の条件（卓の文字 4.5:1・札の地と裏が卓に対して 3:1・スートが札の地に対して 4.5:1 で 4 色が別・手番の印 4.5:1・棒 3:1）・
  どの札を表にするか（メインの子・YOU と ALL・降りた札・ショーダウン・全員が降りたハンドの勝者）・役の名前・チップの区切り・
  卓の列（全卓が優勝で終わる・各歩でチップが変わらない・同じシードで同じ出来事の列・南がメインの子で 4 名が並ぶ・乱数の打ち手が合法な行動だけを選ぶ）
- **不能**: Windows Terminal での見え方（色・幅）は単体テストでは確かめられない（QLT-013）。Phase 3-4 の実機の写真で確かめる

## 結果

- 卓の 4 席・場札・ポット・HUD が 1 画面に入り、`v` で札の見せ方が替わる
- 失うもの: 80 × 24 の端末では卓が出ない（Phase 3-6 で縮小版を足すまで）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| スート記号 `♠♥♦♣` を使う | Emoji=Yes で前景色が効かず（Gambit ADR 0013 の ♟）、Ambiguous の幅の罠もある（画面仕様の決定） |
| 白抜きのスート記号 `♤♡♢♧` を使う | Ambiguous で、実機の写真で 1 桁と確かめられるまで使わない（画面仕様）。まず ASCII で通す |
| VIEW のモードを TableSeries に持たせる | 表示だけの状態が卓の値に入り、`v` で卓の値が変わる形になる（FR-07a） |
| プリフロップでも 2 枚の札から役の名前（ポケットペアなど）を出す | 5 枚未満の札から名前を作る第 2 の経路になる（ARC-001）。Core の役判定は 5〜7 枚 |
| 席の下の直前の行動を Hand の `lastAction` から作る | コールの額がその場で分からない（ストリートの合計は行動の後の値）。Engine の出来事に額を持たせ、LOG と同じ正本から作る |
| ハンドの終わりにも秒読みを出す | 画面仕様の秒読みは卓の終わりだけ。ハンドの終わりは結果を見せる時間だけ待つ |
